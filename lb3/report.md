## Test Design

### calculateDiscount

Перевірено такі Test Conditions та Test Data:

| Test Condition | Test Data | Expected Result |
|---|---|---|

| Знижка понад 100% | price = 100, percent = 110 | Error |

### validateQuantity

Використано Equivalence Partitions та Boundary Value Analysis.

Еквівалентні класи:
- `quantity < 1` — Invalid, очікується `false`.
- `1 ≤ quantity ≤ 10`, ціле число — Valid, очікується `true`.
- `quantity > 10` — Invalid, очікується `false`.
- Неціле число — Invalid, очікується `false`.

Перевірені Boundary Values та додаткове значення: `0`, `1`, `2`, `9`, `10`, `11`, `1.5`.

### getShippingCost

Перевірено такі гілки:

- `total = 999` — вартість доставки 100.
- `total = 1000` — безкоштовна доставка (0).
- `total = -1` — очікується Error.

## Контрольні питання

**1. Що таке Unit Testing?**

Unit Testing (модульне тестування) - це перевірка окремих частин програмного коду, наприклад функцій, щоб переконатися, що вони працюють правильно.

**3. Для чого використовується test() у Vitest?**

`test()` використовується для створення окремого тесту, у якому перевіряється певна поведінка програми.

**4. Для чого використовується expect()?**

`expect()` використовується для перевірки отриманого результату та порівняння його з очікуваним значенням.

**5. Що таке assertion?**

Assertion - це твердження або перевірка, яка визначає, чи відповідає фактичний результат очікуваному.

**6. Що означає схема ААА (Arrange–Act–Assert)?**

Це структура тесту, яка складається з трьох етапів: підготовка даних, виконання дії та перевірка результату.

**7. Що відбувається на етапі Arrange?**

На цьому етапі готуються початкові дані та необхідні умови для тесту.

**8. Що відбувається на етапі Act?**

На цьому етапі виконується дія, яку потрібно перевірити, наприклад виклик тестованої функції.

**9. Що відбувається на етапі Assert?**

На цьому етапі перевіряється, чи відповідає отриманий результат очікуваному.

**10. Для чого використовується describe()?**

`describe()` використовується для групування пов'язаних тестів, наприклад усіх тестів однієї функції.

**11. Для чого використовується toThrow()?**

`toThrow()` перевіряє, чи викликає функція помилку під час виконання.

**12. Чому виклик функції при використанні toThrow() передається всередині іншої функції?**

Тому що `toThrow()` має самостійно виконати передану функцію та перевірити, чи виникла помилка. Якщо викликати її заздалегідь, помилка виникне ще до перевірки.

**13. Для чого використовується test.for()?**

`test.for()` дозволяє запускати один і той самий тест із різними наборами вхідних даних, не дублюючи тестовий код.

**17. Що показує Code Coverage?**

Code Coverage показує, яка частина програмного коду була виконана під час тестування. Основні метрики — Statements, Branches, Functions та Lines.

**19. Чому 100% Coverage не гарантує відсутність дефектів?**

Тому що покриття показує, які частини коду виконувалися, але не гарантує, що всі результати перевірені правильно. Тести можуть не враховувати всі можливі сценарії та помилки.
